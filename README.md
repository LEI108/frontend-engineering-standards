# 正式前端开发规范

> 版本：1.0.0  
> 状态：正式版  
> 发布日期：2026-11-21  
> 适用对象：前端开发者、技术负责人、评审人员和参与前端研发的 AI Agent

本目录是一套可随团队和项目流转的前端工程规范包。它把长期稳定的工程原则、技术栈 Profile、AI 协作治理、Git 追溯、专项 Skill 和任务模板分开维护，避免把某个项目的实现细节误写成通用规则。

## 1. 使用原则

1. **先总纲，后 Profile**：所有项目先遵守框架中立总纲，再加载与技术栈匹配的 Profile。
2. **先事实，后实现**：接口、权限、设计、依赖和运行结论必须有代码、文档或运行证据。
3. **项目配置显式化**：版本、路由模式、响应包裹、分页字段、错误提示和组件注册方式写入项目技术基线，不由通用规范猜测。
4. **Skill 只提供专项工作流**：Skill 不能覆盖正式规范，也不能降低项目的安全、评审和验证要求。
5. **提示词只负责启动**：模板用于传递任务上下文和授权阶段，不复制规范正文。
6. **AI 提交必须先人工审核**：AI 参与的提交在执行 `git commit` 前，必须由实际审核人复核暂存差异。

## 2. 规则层级

发生冲突时，先服从运行环境本身的系统/组织规则，再按以下顺序处理项目内规则：

1. 用户当前请求、已确认决策和合法授权边界；
2. 当前项目及适用子目录的 `AGENTS.md`；
3. 已确认的业务、接口、安全、设计和发布合同；
4. 本包 `standards/` 中的正式规范；
5. 选定的 `profiles/` 和已填写的项目技术基线；
6. `skills/` 中的专项执行流程；
7. `templates/` 中的任务启动文本；
8. 工具默认值、示例和 AI 推测。

Profile 可以细化总纲，不能静默削弱总纲。项目确需例外时，应记录原因、影响、责任人、验证和退出条件。

## 3. 快速入口

| 场景 | 必读内容 | 条件加载 |
| --- | --- | --- |
| 所有前端任务 | `standards/前端工程开发规范（通用版）.md` | 当前项目 `AGENTS.md` 和技术基线 |
| AI 参与分析或开发 | `standards/AI前端协作与分层验证规范.md` | `templates/AI前端开发任务启动模板.md` |
| Vue 3 + TypeScript + Element Plus | 通用总纲 + `profiles/Vue3-TS-ElementPlus基座Profile.md` | `profiles/项目技术基线配置模板.md` 的项目副本 |
| Git 提交 | `standards/Git提交与AI溯源规范.md` | 项目的分支、CI 和 scope 配置 |
| 现有项目小范围修改 | 通用总纲 | `lean-code-edits`、`precision-frontend-engineering` |
| 页面设计或视觉提升 | 通用总纲 | `frontend-design` |
| Lanhu 设计还原 | 通用总纲 + AI 协作规范 | `lanhu-design-build`、Lanhu MCP 集成指南和蓝湖任务模板 |

详细路由见 [规范与技能条件引用向导](guides/规范与技能条件引用向导.md)。

## 4. 目录结构

```text
正式前端开发规范/
├─ README.md
├─ CHANGELOG.md
├─ standards/       # 正式、稳定、具有规范效力的正文
├─ profiles/        # 技术栈 Profile 和项目配置模板
├─ guides/          # 阅读、选择、安装和团队理解向导
├─ integrations/    # 外部工具集成边界，不捆绑外部服务源码
├─ templates/       # 任务、治理、蓝湖和变更记录模板
├─ skills/          # 四份可安装的团队受控 Skill 副本
└─ scripts/         # 安装和完整性检查脚本
```

## 5. 项目接入

推荐在项目内保留本包的版本化副本，或通过团队文档仓库引用固定版本。项目至少应完成：

1. 阅读通用总纲和 AI 协作规范；
2. 选择技术栈 Profile；
3. 复制并填写项目技术基线模板；
4. 在项目 `AGENTS.md` 或贡献指南中声明规范入口和例外；
5. 按需安装 Skill，不要默认同时加载全部 Skill；
6. 将项目实际的质量命令、评审人、变更记录目录和发布流程写清楚；
7. 运行 `scripts/verify-package.ps1` 检查规范包完整性。

## 6. 维护规则

- 通用规则只有在能跨项目成立、可执行且可验证时才进入 `standards/`。
- 框架或组件库特有规则进入 `profiles/`；具体项目事实进入项目技术基线。
- 详细专项流程优先放入 Skill reference，避免总纲无限膨胀。
- 示例只用于说明，不自动成为项目合同。
- 修改规范时同步更新版本、变更记录、受影响链接和校验脚本。
- 不在本包保存 Token、Cookie、`.env`、生产数据、个人敏感数据或本机绝对路径。

本包不覆盖项目本身的架构决策，也不承诺任何代码仅因遵守文档就自动通过运行、视觉、安全或业务验收。

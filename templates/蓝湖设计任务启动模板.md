# 蓝湖设计任务启动模板

> 本模板只负责传入任务参数和阶段授权。权威流程在 `skills/lanhu-design-build/`，实时工具参数以 MCP Tool Schema 为准。

## 参数

```text
业务项目路径：
Lanhu 分享或项目链接：
目标设计名称：
目标路由/页面：
页面类型：普通响应式页面 / 普通图表页面 / 数据驾驶舱或展示墙 / 待判断
当前阶段：交接确认 / 需求讨论 / 已授权只读证据分析 / 已授权实现 / 验证
正式构建口令：开始构建
明确不做：
接口与数据现状：
允许的 Mock 范围：
目标视口和验收范围：
```

## 启动指令

```text
请先加载 lanhu-design-build：
- Skill 已安装时使用 $lanhu-design-build；
- 未安装时完整读取 正式前端开发规范/skills/lanhu-design-build/SKILL.md。

同时读取当前项目 AGENTS.md、正式前端通用总纲、匹配的技术栈 Profile、项目技术基线，
以及 integrations/Lanhu-MCP集成与安全指南.md。

严格区分需求讨论、只读证据分析、业务代码写入和视觉验收授权。
当前阶段没有写入授权时，不修改业务项目。没有只读授权时，不读取 Lanhu 或业务仓库。
不要读取、打印或索要 Cookie、Token 和 .env 内容。

获得只读授权后，按 lanhu-design-build 的条件读取 reference，并以实时 Tool Schema 和
lanhu_get_design_workflow 为工具事实来源。先锁定设计和版本、检查证据完整性、核对目标源码，
再报告 confirmed/tentative/pending/conflicting/risky。证据不足时不要用习惯值或截图猜测冒充精确值。

只有收到“开始构建”且当前授权仍有效后，才按 Skill 的实现映射、首轮运行门和分层验收流程修改。
```

## 阶段交付

```text
设计与版本锁：
证据可用性和缺口：
业务需求与冲突：
目标源码复用：
接口/真实数据/空数据/Mock 边界：
计划修改文件：
设计派生值或偏差：
静态、运行、视觉、交互和数据验证：
未解决与人工验收：
```

不要把“构建成功”“页面可打开”或“局部截图接近”表述为完整视觉还原。

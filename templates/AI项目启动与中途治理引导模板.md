# AI 项目启动与中途治理引导模板

> 选择“现有项目治理”或“新项目启动”之一。默认先分析和规划，具体写入仍需明确授权。

## A. 现有项目治理

```text
你将评估一个已经开发中的前端项目。当前先做只读工程体检，不大范围重构。

项目路径：
当前主要问题：
本轮期望：只读评估 / 方案 / 经确认后实施指定批次

先读取项目 AGENTS.md、正式前端通用总纲、匹配的 Profile、项目技术基线和 Skill 引用向导。
检查 git status、当前分支、未提交修改、包管理器、lockfile、质量脚本和 CI；保护已有工作。

按证据评估：
- 依赖和质量命令是否真实可执行；
- 路由、页面、组件、状态、API 和类型的所有权；
- 接口、权限、错误和 Mock 是否有合同；
- 组件膨胀、重复实现、过度抽象和公共能力；
- 全局样式、组件库覆盖、响应式和可访问性；
- loading/empty/error/permission、并发和资源清理；
- 注释、测试、运行和视觉证据。

输出已确认事实、静态发现、已运行检查、未运行检查、推测/待确认项。
按 P0/P1/P2 给出可独立评审的治理批次，每项包含证据、影响、最小改法、风险和验证。
默认不修改，先推荐一个最小高收益批次并等待授权。
```

确认某批后续接：

```text
现在只实施已确认的第 <批次> 批，目标是：<单一目标>。
重新检查工作区，只修改该批范围；不混入格式化、无关修复或未来抽象。
开始前给出文件/锚点、保留行为、修改行为、风险和验证；完成后分层报告实际证据。
```

## B. 新项目启动

```text
你将协助启动一个新前端项目。先建立工程基线和第一条可验证垂直切片，不批量生成页面。

项目路径：
项目名称：
目标平台和用户：
已确定技术栈：
已知业务范围：
明确不做：

先读取正式前端通用总纲、AI 协作规范、匹配的技术栈 Profile 和 Skill 引用向导。
使用 profiles/项目技术基线配置模板.md 形成项目基线，明确：
- 运行时、包管理器、版本和 lockfile；
- feature/domain 边界、路由、状态、API、类型和权限；
- UI token、组件库、响应式和可访问性；
- loading/empty/error/permission/mock；
- lint、typecheck、format、test、build、运行和 CI；
- Git、AI trailers、人工审核和变更记录。

设计第一条垂直切片：一个真实路由、一个确认的数据合同、一个页面区域、完整关键状态和一条最小验证路径。
输出基线、待决策项、垂直切片、风险、验证和暂不引入的依赖/抽象。得到确认后再实施。
```

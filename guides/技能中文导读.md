# 团队 Skill 中文导读

> 四份 Skill 的英文 `SKILL.md` 和英文 reference 是 AI 执行权威。本文只帮助团队选择和阅读，不逐段翻译，也不覆盖 Skill 原文。

没有恢复 `frontend-design` 过去的 13 份中文镜像。完整双语镜像会产生两套规则同步和漂移成本；本包改用一份中文路由表，并由正式中文规范承载团队治理要求。

## 1. frontend-design

入口：`skills/frontend-design/SKILL.md`

适用：新页面、界面视觉、设计系统、响应式、可访问性、动效、性能和最终 UI 复核。

| Reference | 中文用途 |
| --- | --- |
| `design-contexts.md` | 判断新颖程度、产品密度和既有设计系统约束 |
| `project-architecture.md` | 项目结构和模块边界 |
| `naming-conventions.md` | 文件、组件、hook/composable 和工具命名 |
| `component-and-utils.md` | 组件与工具抽取判断 |
| `style-architecture.md` | token、全局样式、局部样式和覆盖层 |
| `vue.md` | Vue 场景的实现注意事项 |
| `react.md` / `vanilla-web.md` | 对应技术栈的条件指南 |
| `accessibility.md` | 键盘、语义、焦点、对比度和状态检查 |
| `motion-performance.md` | 动效和渲染成本 |
| `performance-optimization.md` | 网络、包体、资源和运行性能 |
| `review-checklist.md` | 交付前 UI 复核 |

## 2. lanhu-design-build

入口：`skills/lanhu-design-build/SKILL.md`

适用：从 Lanhu 设计稿获取证据、锁定版本、实现页面、处理图表/大屏并完成分层视觉验收。

| Reference | 中文用途 |
| --- | --- |
| `lanhu-evidence.md` | 工具顺序、版本锁、完整性、来源和失败报告 |
| `code-quality.md` | 注释、结构、运行选择器和派生 CSS |
| `acceptance.md` | 实现映射、首轮运行门和验收阶梯 |
| `chart-runtime.md` | 图表证据、生命周期、状态和动态数据 |
| `data-dashboard.md` | 仅数据驾驶舱/展示墙使用的缩放、轮播和自动滚动分支 |

该 Skill 依赖外部 Lanhu MCP，安装和安全边界见 `integrations/Lanhu-MCP集成与安全指南.md`。

## 3. lean-code-edits

入口：`skills/lean-code-edits/SKILL.md`

适用：bug 修复、聚焦功能、小型重构和日常维护。核心是：只提出有影响的问题、用最小实现完成任务、只动必要范围、按风险做最小验证。

Skill 入口会读取同目录 `AGENTS.md`。该文件是 Skill 自身行为合同，不会替代目标项目的 `AGENTS.md`。

## 4. precision-frontend-engineering

入口：`skills/precision-frontend-engineering/SKILL.md`

适用：现有前端应用的功能、API、UI、复用和维护。

| Reference | 中文用途 |
| --- | --- |
| `change-safety-and-scope.md` | 工作区保护、语义锚点和小范围差异 |
| `api-contracts-and-mocks.md` | API、响应、Mock、上传和下载合同 |
| `component-reuse-and-boundaries.md` | 组件、页面、表格、状态和样式所有权 |
| `comments-and-handoff.md` | 有效注释和可复制修改交接 |
| `focused-verification.md` | 任务级检查、运行选择器和视觉边界 |

## 5. 阅读约定

- AI：必须完整读取触发的 `SKILL.md`，再按入口的条件读取相关 reference。
- 开发者：先读本导读和正式规范；需要评审专项流程时再查英文 reference。
- 维护者：更新英文权威文件后同步本导读的路由和摘要，不复制整段正文。
